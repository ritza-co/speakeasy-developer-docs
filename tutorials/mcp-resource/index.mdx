Many developers skip MCP resources because they seem similar to MCP tools as both can read data. But there's a key difference that makes resources incredibly useful for agentic workflows. Resources give your LLM direct access to knowledge bases like documentation and codebases, eliminating the need to manually find and paste relevant information into every conversation. For example, instead of manually finding and copying a project's `README.md` file when asking installation questions, you can set up the README as a resource so Copilot automatically has access to the specific setup instructions during the conversation.

In this tutorial, we will:

- Set up Sentry with Claude Desktop so you can ask specific integration questions and get answers that reference current Sentry documentation and best practices.

- Set up GitHub MCP server with VS Code so Copilot can read the axios `README.md` and suggest implementation steps based on the actual library documentation.

## Prerequisites

Before starting this tutorial, you'll need:

- [Claude Desktop](https://claude.ai/download) with a Pro or Team plan (required for MCP resources).
- [VS Code](https://code.visualstudio.com/) with [GitHub Copilot](https://github.com/copilot) enabled.
- A GitHub account with a [personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#creating-a-fine-grained-personal-access-token).
- An active Sentry account (free tier works).

## Tools vs. resources

Both [tools](/mcp/tools) and [resources](mcp/resources) can handle read-only operations, and both can be used by you or the AI agent to fetch data for context. The key difference is how much content they return.
Tools are well-suited for quick data lookups, retrieving a user's profile, checking status, or running a simple query. Resources are designed for extensive reference material, such as comprehensive documentation, complete log files, entire configuration files, or substantial codebases that remain available as context throughout the entire conversation with the LLM.
If your read-only operation returns extensive text or complete files or media material, use a resource. If it returns a specific data point or status update, use a tool to process it.

## Claude Desktop + Sentry MCP

Claude Desktop supports MCP resources on Pro and Team plans but doesn't support resource templating, meaning you can't pass dynamic parameters to customize what the resource fetches.
The [Sentry MCP server](https://docs.sentry.io/product/sentry-mcp/) provides documentation for integrating Sentry with different platforms.

We'll connect the Sentry MCP server to Claude Desktop so that we can ask questions about Sentry iOS integration directly in our conversations to get accurate setup instructions and troubleshooting help without leaving our development environment.

### Configure Sentry MCP in integrations

Open Claude Desktop settings by clicking on your username in the bottom left and then choosing Settings in the pop up menu. Go to the Integrations section and click **+ Add integration**. Enter the integration name and set the URL to `https://mcp.sentry.dev/mcp`.

<Screenshot url="./assets/claude-adding-sentry.png">![Configuring Sentry MCP Integration](./assets/claude-adding-sentry.png)</Screenshot>

Click **Connect** to authorize Sentry access to your organization. You'll be redirected to confirm access in your browser. You will need to be logged in to your Claude account in your browser to initiate the authorization flow.

<Screenshot url="./assets/claude-sentry-mcp-integration.png">![Connecting Sentry and Claude](./assets/claude-sentry-mcp-integration.png)</Screenshot>


### Add Sentry documentation as context

In any chat, click the **+** button. Select **Add from Sentry** from the options.

<Screenshot url="./assets/claude-finding-resources.png">![Adding Sentry resources](./assets/claude-finding-resources.png)</Screenshot>

Choose the **Apple iOS guide** documentation from the list.

<Screenshot url="./assets/claude-looking-for-ios-guide.png">![Selecting Apple iOS guide](./assets/claude-looking-for-ios-guide.png)</Screenshot>

The resource has been attached. You can then send a prompt to ask for a guide to set up Sentry for your iOS project.

### Test the setup

With the resource attached, ask Claude: "How do I set up Sentry crash reporting for my iOS project?".

<Screenshot url="./assets/mcp-resources-sentry-testing.png">![Testing the setup](./assets/mcp-resources-sentry-testing.png)</Screenshot>

In the image above, Claude responds with detailed iOS setup steps, including specific Swift code and configuration details. With the Sentry documentation as context, it can provide accurate, platform-specific guidance rather than generic crash reporting advice.

## GitHub MCP server with VS Code

VS Code with GitHub Copilot supports MCP servers and resources. We'll set up the GitHub MCP server in VS Code so that we can include the [axios](https://github.com/axios/axios) `README.md` file as context and ask Copilot for implementation help that references the actual library examples and API methods.

### Create the MCP configuration

In your project root, create a file named `mcp.json` in the `.vscode` directory and add this configuration:

```json
{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${input:github_mcp_pat}"
      }
    }
  },
  "inputs": [
    {
      "type": "promptString",
      "id": "github_mcp_pat",
      "description": "GitHub Personal Access Token",
      "password": true
    }
  ]
}
```

Once the file is saved, VS Code will detect the configuration and show a Start button above the configuration. Click this button to start the MCP server, and you will be prompted to enter your GitHub personal access token.

### Add GitHub file as resource

In any Copilot chat panel in VS Code, click the **📎 Add Context...** button. Select **MCP Resources**.

<Screenshot url="./assets/mcp-resources-vscode.png">![Adding MCP resources](./assets/mcp-resources-vscode.png)</Screenshot>

Choose the **repository content** template. Enter:

- Repository owner: `axios`
- Repository name: `axios`
- File path: `README.md`

<Screenshot url="./assets/mcp-github-content.png">![Selecting LICENSE file](./assets/mcp-github-content.png)</Screenshot>

### Test the setup

With the `README.md` file attached as context, write: *Give the steps you will follow to set up axios in this project.*

<Screenshot url="./assets/using-resource.png">![Testing the setup](./assets/using-resource.png)</Screenshot>

In the image above, we can see that Copilot is suggesting an implementation plan for integrating axios into the current project, referencing specific methods and examples from the axios README that's now available as context.
